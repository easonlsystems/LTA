## Production gaps requiring decision

- **Extraction backup:** select and fund a provider, set `MEDIA_PROVIDER_URL` and any required key on the worker, then live-test its metadata/audio/identity contract. The current `no_audio_stream` case has no such route. Code-only fix: no.
- **ASR backup:** select/fund OpenAI or another compatible service and provide a worker key. Current Groq failure exhausts the chain. Code-only fix: no.
- **Region:** decide whether a second worker in SFO or another region is justified by failure rate and cost, and define region routing beyond YouTube `GEO_BLOCKED`. Current Amsterdam-only topology cannot fail over. Code-only fix: no.
- **Top-up:** create approved Lemon Squeezy one-time variants, set both IDs, validate signed paid/refunded webhook order and job resume in a safe mode. Current paid accounts cannot see a top-up checkout. Code-only fix: no.
- **Reddit:** production lacks `REDDIT_CLIENT_ID`/`REDDIT_CLIENT_SECRET`. README and PRODUCT correctly make Reddit conditional; the live `/sources` page omits it. Providing approved OAuth access is a product/platform decision, not a code bug. Current source status: BLOCKED.
- **Offsite backup:** the scheduled workflow has been skipped repeatedly through 2026-11-23; `docs/TOPUP_BACKUP_STATUS.md` explicitly says it stays disabled until an enable variable and storage/crypto secrets are supplied. A backup/retention decision and restore drill are needed. No evidence claims that an offsite backup currently exists.

### Runtime reconciliation and fallback limits

Railway live API has DB, app/auth/Google/Resend, Lemon Squeezy subscription credentials and Basic/Pro variants; it lacks both top-up variants and Reddit OAuth. Worker has DB, yt-dlp/FFmpeg paths and Groq; it lacks external extractor, OpenAI ASR, Reddit OAuth and `WORKER_REGION_ORDER`. Docker pins yt-dlp, gallery-dl, youtube-transcript-api, ffmpeg and Python; worker startup probes yt-dlp/FFmpeg/curl-cffi, while `/readyz` checks config and two schema fields, not third-party reachability. API, worker and DB each run one Amsterdam replica.

The deployed worker's `worker_started` event on 2026-11-19 07:33 UTC reports `region=ams` and `worker_concurrency=4`. This confirms the running limit, rather than inferring it from the default or variable name.

Railway distributed tracing is disabled for every production service. Current provider and job logs are therefore the available cross-step evidence, making the fixed `job_ref` correlation material. Enabling tracing is an operations/cost decision and was not performed.

The external metadata/audio fallback is attempted only for `EXTRACTION_FAILED`, `RATE_LIMITED` or `PLATFORM_BLOCKED`; it is not triggered for private/login/geo/not-found cases. X audio has an additional syndication → yt-dlp path, including selected media errors. Caption rejection leads to audio/ASR; Groq failure or transcript-quality rejection can reach OpenAI only when its key exists. YouTube's transcript helper is a separate metadata-failure route. Cache reuse happens after canonical metadata for video and before extraction for text, so a provider outage can still block an uncached video before a cached transcript is found. Production lacks evidence of any successful configured external, OpenAI or cross-region failover.

### Billing, queue, security and readiness checks

- Code uses reservation before expensive ASR, a unique `usage_ledger.job_id`, and transactional ledger-plus-job completion. Failure handlers release reservations, but pre-fix logs did not expose whether release succeeded; this branch adds `quota_reservation_release` outcome. Production ledger, refund and duplicate-charge queries were unavailable.
- Worker claims queued jobs with `FOR UPDATE SKIP LOCKED`, locks the user row and recounts active jobs against plan concurrency. Claim increments attempts; media-claim and region deferrals decrement it. A 60-second heartbeat extends job lock, quota reservation and media claim; maintenance requeues jobs stale for 10 minutes. A configured destination region with no actual worker could strand a job, but present default is only Amsterdam.
- `safeGetBuffer` requires HTTPS, checks every redirect's DNS/IP for public addresses, pins the resolved address for TLS requests, limits bytes and time, and requests identity encoding. Platform-specific extractors and CDN response behavior still need live hostile-input certification. External metadata validates canonical identity. No confirmed SSRF exploit was established.
- Migration runner serializes API/worker predeploy attempts with an advisory transaction lock and replays 001–016 in current production; deploy logs show completion. This branch adds idempotent 017 for refresh intent. The deployed `schemaReady()` checks only `transcript_jobs.error_cause_code` and `transcript_cache.media_validated`; that cannot certify all ledger, OAuth, billing and analytics constraints. No live schema drift was proven.

**Is current LTA production actually reliable enough for normal users? NO.** A Reel read has failed in current production, extraction/ASR and region backups are absent, top-ups cannot be purchased despite the product claim, and most sources lack fresh live verification. This does not mean every source fails.
